Write a runtime tool

Mark a static method with [MatrixRuntimeTool]. Add [Preserve] so code stripping keeps it in builds, and describe every parameter: the client reads the descriptions.

using System.ComponentModel;
using Feeder.MCP.Player;
using UnityEngine.Scripting;

[Preserve]
[MatrixRuntimeTool("runtime-hello", ReadOnly = true, Description = "Greets from the running game.")]
static string Hello([Description("Who to greet.")] string name = "world") => "hello " + name;

Code in Assembly-CSharp sees the attribute as is. Code in its own assembly definition needs a reference to Feeder.MCP.Player.

Set ReadOnly = true only when the method changes nothing. Two samples ship with the package: runtime-ping and runtime-scene-info.

Link Play mode

  1. Switch it onChoose [[menu:Tools > Feeder > Matrix Bridge > Server > Link Play Mode As Player]].
  2. Press PlayEach Play session links to the server as a player. The Editor link stays up.
  3. AskYour client now lists your runtime tools and can call them while the game runs.

Link a build

Start the game with the server's port and token on the command line:

MyGame.exe -matrixPort <port> -matrixToken <token> [-matrixHost <host>] [-matrixProject <id>]

Or connect from code with Feeder.MCP.Player.MatrixPlayer.Connect(host, port, token). The port is the one in the project's .mcp.json; the token is the token value in UserSettings/Feeder-MCP-Config.json. The token can also come from the MATRIX_PLAYER_TOKEN environment variable.

PlatformsDesktop and mobile players. WebGL builds cannot link.
