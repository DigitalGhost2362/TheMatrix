Experimental, Windows onlyOff by default. Only a person can turn it on, from [[menu:Tools > Feeder > Matrix Bridge > Hyper Testing (Experimental)]]. The switch is per machine and per project, and turns off again on every package update.

Turn it on

  1. Open the windowChoose [[menu:Tools > Feeder > Matrix Bridge > Hyper Testing (Experimental)]] and switch it on.
  2. Restart Claude Code onceSo it picks up the play tester definitions in .claude/agents/.
  3. Ask for a runFor example: "Run the test cases in TestCases/ on three clones." Your client follows the matrix-hyper-testing-guide skill: it creates the clones, splits the cases and starts the play testers.

What a clone is

  • Clones live in <project>.HyperClones/hc<N>. Their Assets and embedded packages are links to your project; each clone has its own Library and its own server port.
  • Clones start one after another and open no scene on start.
  • After a code change, refresh recompiles the clones one at a time.

Know before you start

  • Memory. Windows runs out of commit memory before free RAM. up refuses a clone that would not fit, keeping ramReserveMb free, and a GPU with 4096 MB or less starts one clone. Samples go to HyperTesting/Journal/ram-samples.csv.
  • Clones write into your project. An asset a clone creates is created in your project. Each one is reported as CRITICAL, and down and status warn about new untracked files. Packages that write under Assets/ when play starts do not work with clones.
  • Results go to HyperTesting/Runs/, the journal to HyperTesting/Journal/. Settings are in HyperTesting/config.json.
Remove clones with the buttonUse Delete clones in the Hyper Testing window. Never delete a clone folder by hand with a recursive delete: its Assets is a link to your project, and the delete can follow it.

Driving a clone by hand

HyperTesting/tools/ holds hc.py, hx.sh, hxf.sh and shot.py, which call a clone over HTTP when a play tester has no MCP tools for it.
