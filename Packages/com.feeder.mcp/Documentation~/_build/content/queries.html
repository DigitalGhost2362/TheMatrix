You do not need to learn it: your client writes the queries. This page helps you read what it is doing, and write one yourself when you want to.

Three tools

ToolDoesOn after Setup
[[tool:rql-query]]Reads the open scenes (or the open prefab), assets, the Console and the selection. Answers with a compact table or JSON. Refuses anything that changes the project.Yes
[[tool:rql-schema]]Prints the syntax, the functions and the component types in the open scenes. With typeName, the members of one type and which can be written.Yes
[[tool:rql-mutate]]Changes things: set, call, add, destroy, or creates objects with new(...).No: switch it on in the Skills window

The shape of a query

A source, then stages separated by |. Each stage takes the rows of the previous one.

objects | where Light.intensity > 1 | select name, Light.intensity, $path | sort Light.intensity desc
PartChoices
Sourcesobjects (every GameObject in the open scenes or prefab), roots, selection, scenes, logs, components("Type"), prefab, assets("t:Material", "Assets/Folder"), asset("Assets/x.mat"), find("Path/Or/Name")
Stageswhere, select, sort, take, skip, first, last, count, distinct, group, sum / avg / min / max, get, components, children, descendants, parent
Membersname, transform.position.x, a component by its type such as Light.intensity, material["_BaseColor"], and $path, $type, $id, $index
Operators== != < <= > >=, and or not, contains startswith endswith (ignore case), matches (regex), in [..], is Type, is null
Change stagesset PATH = VALUE, call Method(args), add Type, destroy: [[tool:rql-mutate]] only

Examples to read

# how many objects of each tag are in the scene
objects | group tag

# renderers that still use the default material
components("MeshRenderer") | where sharedMaterial.name == "Default-Material" | select gameobject.name, $path

# the last ten errors in the console
logs | where type == "Error" | take 10

# which shader each material under Assets/Materials uses
assets("t:Material", "Assets/Materials") | select name, shader.name

Examples that change things

# move and rename one object
find("Player") | set position = [0, 1, 0], name = "Hero"

# heavier enemies
objects | where name startswith "Enemy" | set Rigidbody.mass = 2

# give every pickup a collider
objects | where tag == "Pickup" and not has("SphereCollider") | add SphereCollider

Safety rails on changes

  • All or nothing. Every target is checked before anything changes. One bad target, no change at all.
  • One undo step named Matrix query. Ctrl + Z reverts the whole query.
  • dryRun=true lists every change and then reverts it. Ask your client for a dry run on anything large.
  • maxTargets (default 100) refuses a change wider than that.
  • Nothing is saved for you. Scenes and assets are marked dirty; save=true saves what the query touched.

What queries do not do

Actions a query cannot express keep their own tools: opening, saving and unloading scenes, prefab mode, copying, moving and deleting assets, play mode, the Console, scripts, tests, packages, screenshots, the profiler and builds. Find them in the tool catalog.

From your own Editor code, Feeder.MCP.Editor.Query.MatrixQuery.Run and MatrixQuery.Mutate take the same queries.
