Everyday use

Matrix in a team project

Commit the package with the project; keep the per-machine files out. Teammates who never run Setup see no change at all.

Who is affected#

  • Teammates who never run Setup: nothing starts, opens or is written for them, even when the package is in Packages/manifest.json. A saved window layout that includes Matrix windows does not open them either.
  • Teammates who run Setup: Matrix turns on for that machine and that project folder only. The choice lives outside the project and is never committed.

What to commit and what to ignore#

PathCommit?Why
Packages/manifest.json with the git URLYesEveryone gets the same package version.
.mcp.json, .codex/config.tomlNoThey hold this machine's port. Setup adds both to .gitignore.
.cursor/mcp.json, .vscode/mcp.json, .gemini/settings.json and other client filesNoSame reason. Setup does not ignore these: add the ones you wire to .gitignore yourself.
.claude/skills/matrix-*/Your choiceMatrix adds and deletes one folder per tool as tools are switched on and off. Ignore <skills folder>/matrix-*/, or accept the changes in your diffs.
UserSettings/Feeder-MCP-Config.jsonNoPort, token and tool switches for this machine. Unity's standard ignore rules already skip UserSettings.
ProjectSettings/ProjectSettings.assetYesSetup turns Run In Background on here. It is a normal project setting.
.mcp.json was already committedSetup prints the command to run. When the file holds only the Matrix entry, it is git rm --cached .mcp.json. When it also holds other servers your team shares, keep it tracked and run git update-index --skip-worktree .mcp.json on your machine instead, so a pull never deletes the file for teammates.

Names Matrix uses#

Matrix only creates, edits and deletes things under its own names, so it never touches your other tools:

  • the server in Library/feeder-matrix and its log in Temp/feeder-matrix;
  • the Feeder-MCP entry in .mcp.json and the other client configs;
  • environment variables that start with FEEDER_MATRIX_;
  • skill folders named matrix-*;
  • data types in the Feeder.MCP.Data namespace.

It never edits or deletes a server entry, skill or config that it did not write.

Two copies of one project#

Each folder gets its own port, so two clones of the same project can run Matrix side by side. Start each client in the folder of the copy it should work on.
